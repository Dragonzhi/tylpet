# v0.1.0-preview.3 开发计划：陪伴行为导演

> 状态：待实施
>
> 对应里程碑：M17
>
> 计划日期：2026-07-30
>
> 前置版本：[`v0.1.0-preview.2`](https://github.com/Dragonzhi/tylpet/releases/tag/v0.1.0-preview.2)

本文档定义 Preview.3 的单版本范围、实施顺序、架构边界和验收门。长期愿景以 [`HANDBOOK.md`](../HANDBOOK.md) 为准，工程约束以 [`AGENTS.md`](../AGENTS.md) 为准，跨版本依赖以 [`计划.md`](../计划.md) 为准。

## 1. 版本定位

Preview.2 已经验证角色模式、对话、受控 Agent、TTS、记忆、系统音乐反应、创作者插件和发布链路能够稳定共存。Preview.3 不继续横向增加大型能力，而是解决当前最明显的体验缺口：

> 小洛宝拥有很多可调用功能，但缺少一个把现有动作、状态和事件组织成自然日常的本地行为导演。

本版本目标是让角色在不联网、不调用 LLM、不读取更多系统信息的情况下，偶尔做出可解释、低频、可立即打断的反应。她应该显得活着，但不能像通知中心一样持续抢夺注意力。

## 2. 先确定的产品决策

### 2.1 美术不是开工条件

首个完整闭环必须只使用已经发布的能力：

- `wave`
- `bow`
- `stretch`
- 现有眨眼、呼吸、鼠标跟随、睡眠、TTS 口型和音乐律动
- 已有头部、眉眼、耳朵和头发的程序化动态

缺少某个可选动作时，动作目录选择已有替代项或安全地不执行，不得让桌宠空白、卡死或反复报错。`yawn`、专用 `listen`、开心或惊讶动作属于后置增强，每次最多引入一个经过 Animation Studio 完整发布链路验证的 Clip。

### 2.2 默认本地、确定性、无模型费用

`CompanionDirector` 是本地纯策略，不是后台 Agent：

- 不自动请求外部 Provider。
- 不把空闲时间、窗口状态、媒体状态或插件事件发送给模型。
- 不访问聊天正文、记忆正文、文件、进程、窗口标题或终端内容。
- 不产生任意工具参数，只提交已有的语义动作请求。
- 模型和插件都不能修改自主陪伴设置、角色模式或频率预算。

未来如果增加“模型主动发起对话”，必须作为独立版本重新设计授权、费用、频率、上下文和隐私边界，不借 Preview.3 的本地导演暗中实现。

### 2.3 安静优先于活跃

- 陪伴模式允许低频空闲动作。
- 专注模式显著延长空闲间隔，计时期间不得抢占专注反馈。
- 安静模式和休眠模式不产生空闲动作。
- 用户操作、拖动、菜单、聊天、计时提醒、安全停止和退出始终高于自主行为。
- `prefers-reduced-motion` 与动画强度继续具有更高约束力。

## 3. 交付范围

### 3.1 纯策略行为导演

新增可独立测试的 `CompanionDirector`。输入是脱敏的运行时快照，输出是“执行、等待或不执行”的决定；它本身不持有 React 节点、不调用 Tauri、不启动计时器，也不直接播放动画。

建议的最小输入：

```ts
interface CompanionSnapshot {
  nowMs: number;
  mode: "companion" | "focus" | "quiet" | "sleep";
  petState: "idle" | "blink" | "listen" | "speak" | "sleep" | "drag";
  lastUserInteractionAtMs: number;
  lastAmbientActionAtMs: number | null;
  activeActionSources: readonly string[];
  availableMotions: readonly string[];
  reducedMotion: boolean;
  autonomyEnabled: boolean;
  idleFrequency: "low" | "normal";
}
```

建议的输出：

```ts
type CompanionDecision =
  | { kind: "wait"; nextCheckAtMs: number; reason: string }
  | { kind: "skip"; reason: string }
  | { kind: "act"; cue: CompanionCue; motion?: string; cooldownKey: string };
```

测试应注入时钟和带种子的随机源，不能依赖真实时间或不可复现的 `Math.random()`。

### 3.2 运行时桥接

新增轻量 `CompanionRuntimeBridge`：

1. 订阅角色模式、设置、角色状态和用户交互时间。
2. 在下一次候选时间到达时调用纯策略导演。
3. 将决定转换为低优先级 `ActionRequest`。
4. 通过现有 `BehaviorScheduler` 提交、观察结果并记录脱敏诊断。
5. 在设置关闭、模式收紧、用户操作、HMR 或组件卸载时清理 timeout、监听器和待处理请求。

不得在组件 render 中读取当前时间并期待自动刷新，也不得建立每帧轮询。一次只保留一个可清理的下一次唤醒计时器；系统休眠或长时间暂停后不补播错过的动作，而是重新计算下一次窗口。

### 3.3 动作目录与降级

新增与渲染器能力快照解耦的动作目录：

| 语义 cue | 首选表现 | 降级 | 硬失败行为 |
|---|---|---|---|
| `idle.stretch` | `stretch` | 保持待机 | 不重试、不弹错误 |
| `user.greet` | `wave` | 程序化抬头/关注 | 保持待机 |
| `task.complete` | `bow` 或 `wave` | 现有轻粒子/表情 | 只保留原通知 |
| `chat.listen` | `listen` 状态与头部关注 | 现有鼠标/头部跟随 | 不影响聊天 |
| `music.playing` | 现有音乐律动 | 无 | 不额外提交重复 Clip |

目录只接收稳定语义名和能力集合，不接收 DOM ID、CSS selector、原始 SVG 图层或 Tauri command。

### 3.4 `listen` 状态闭环

当前 `listen` 只有状态骨架。本版本使它在以下路径真实可达：

```text
idle ──用户在绨络对话框输入──> listen
listen ──开始生成───────────> listen / 关注
listen ──TTS 开始───────────> speak
speak ──TTS 结束或中断──────> idle
listen ──输入取消或窗口关闭──> idle
```

跨窗口只传递 `{ active: boolean }` 或枚举状态，不传输入内容。`listen` 首版使用已有头部、眼睛、眉毛和耳朵动态表达，不要求新增 SVG 图层或 Clip。

### 3.5 设置与迁移

设置 schema 预计从 v10 升至 v11，新增独立分组：

```ts
interface CompanionSettings {
  autonomyEnabled: boolean;
  idleFrequency: "low" | "normal";
  particlesEnabled: boolean;
}
```

默认建议：

- `autonomyEnabled: true`
- `idleFrequency: "low"`
- `particlesEnabled: true`

默认开启只允许离线、低幅度、低频视觉行为；设置页必须提供一句话说明和立即关闭入口。升级迁移不得修改 Agent、Provider、TTS、记忆、观察、模式或 API key 状态。

模式策略只计算有效能力：安静/休眠时临时关闭自主陪伴，切回陪伴后才按用户总开关恢复，不能把用户保存的开关改写为 `false` 或 `true`。

### 3.6 克制的反馈效果

首版只复用现有音乐粒子或使用简单 SVG/CSS 几何形状，不增加新的位图素材：

- 任务完成：一小组星光，短时间自动消失。
- 音乐播放：继续使用现有音符/粒子律动，不叠加第二套反应。
- 休眠：可以使用一个低频、低透明度睡眠符号；如果实现会扩大素材或层级复杂度则推迟。

效果必须：

- `pointer-events: none`，不能改变点击穿透命中。
- 有数量上限，完成后移除节点和动画。
- 跟随动画强度；reduced motion 下静态淡入淡出或完全关闭。
- 不使用全屏覆盖层，也不扩大 `400 × 500` 主窗口。

## 4. 默认频率与安全预算

以下是首轮实现基线，最终数值集中到配置文件并通过真实试用调整：

| 规则 | 陪伴模式 | 专注模式 | 安静/休眠 |
|---|---:|---:|---:|
| 启动/用户操作后的保护期 | 120 秒 | 180 秒 | 不触发 |
| 低频候选间隔 | 8～15 分钟 | 18～30 分钟 | 不触发 |
| 标准候选间隔 | 4～9 分钟 | 12～20 分钟 | 不触发 |
| 同一动作冷却 | 至少 20 分钟 | 至少 30 分钟 | 不触发 |
| 每小时空闲动作上限 | 6 次 | 3 次 | 0 次 |

补充规则：

- 连续两次不能选择同一动作。
- 调度器拒绝、能力缺失或动作被中断时，不立即换一个动作重试。
- 从系统休眠恢复后重新开始保护期。
- 聊天、拖动、菜单和用户直接动作完成后重新开始保护期。
- 计时完成、插件状态和系统音乐已有各自入口，导演不得重复消费同一事件制造双重反馈。

## 5. 实施阶段

### P3-A：契约、设置与纯策略

目标：不改视觉也能完整测试“什么时候可以做什么”。

- 增加 `CompanionSettings`、v11 迁移和设置测试。
- 实现快照、cue、decision、动作目录和纯策略选择器。
- 注入时钟与随机源，测试间隔、冷却、预算、去重和模式策略。
- 明确调度来源 `ambient`，优先级低于用户、设置、计时和 Agent。
- 设置页加入自主陪伴、频率和粒子开关及有效状态说明。

完成门：所有策略可在 Vitest 中使用虚拟时间确定性复现；此阶段不需要新动画。

### P3-B：运行时接入与现有动作闭环

目标：只用 `stretch` 完成第一条真实自主行为链路。

- 实现 `CompanionRuntimeBridge` 和完整 cleanup。
- 记录用户交互与系统恢复后的保护期。
- 通过调度器提交、完成、中断或拒绝自主动作。
- 能力缺失时安全 no-op，不污染错误提示或循环重试。
- 将有限的 cue、动作名和结果加入现有脱敏诊断。

完成门：真实 Tauri 窗口中可以临时缩短配置观察自主 `stretch`，拖动或安全停止能立即中断，恢复正式配置后长时间运行稳定。

### P3-C：`listen` 与对话状态

目标：让角色对用户正在和她交流这件事有明确但安静的视觉反馈。

- 对话窗口只发送输入活跃/生成/TTS 枚举，不发送文字。
- 主窗口将其映射为持续状态，而不是短暂动作队列。
- 正确处理输入取消、窗口关闭、生成错误、TTS 中断和重复打开。
- 确保 `listen`、`speak`、`sleep`、`drag` 之间只有一个合法持续状态。

完成门：状态没有卡死；关闭聊天或中断朗读后恢复此前合法模式状态。

### P3-D：事件协调与轻量反馈

目标：减少已有能力之间“各自反应一次”的割裂感。

- 为计时完成、插件完成/失败和音乐播放定义统一 cue 名称与去重键。
- 保留 `ObservationHost`、TimerController 和插件安全边界，不让导演读取原始 payload。
- 同一语义事件只产生一次角色反馈。
- 加入短时、限量、不可命中的简单粒子效果。

完成门：计时、媒体或插件事件不会与空闲动作同时争抢角色；失败反馈不伪装成成功。

### P3-E：可选动作增强

目标：在程序闭环稳定后，用 Animation Studio 增加最多一个高复用动作。

候选优先级：

1. `yawn`：最符合长时间陪伴，但需要新动作。
2. `listen`：若程序化姿态不够清晰，再制作专用 Clip。
3. `happy`：可复用在计时、插件和对话完成。

实施要求：

- 使用正式 `artwork + rig + motions` 项目，不手改生产 JSON。
- 发布前验证 fingerprint、绑定、层级和 bind pose 回归。
- 新动作缺失时 Preview.3 的核心体验仍然成立。

完成门：这是增强门，不是版本发布硬门；美术未准备好时可以跳过并在计划中说明。

### P3-F：验收与发布准备

- 更新 `HANDBOOK.md` 中真正完成的路线项。
- 新增 Preview.3 验收报告和 CHANGELOG 段落。
- 完成自动化、真实 Tauri、安装/覆盖升级和长时运行测试。
- 最后才将根 `VERSION` 同步为 `0.1.0-preview.3` 并构建 NSIS 候选。

## 7. 自动化验证

最低测试覆盖：

- v10 → v11 设置迁移不丢失任何现有字段。
- 陪伴、专注、安静、休眠四种模式的有效策略。
- 用户操作保护期、时间窗口边界和系统休眠恢复。
- 每小时预算、同动作冷却和连续动作去重。
- 带种子随机在相同输入下产生相同结果。
- `stretch` 缺失时 no-op，不重复提交。
- 调度器拒绝、中断和 cleanup 后不遗留 timeout。
- listen → speak → idle，以及关闭/错误/中断路径。
- 粒子数量上限、完成清理和 reduced motion 降级。
- 诊断不包含聊天、记忆、窗口标题、插件 payload 或模型参数。

实施完成后运行：

```powershell
node --version
npm ls --depth=0
npm test
npm run artwork:check
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
cargo check --manifest-path src-tauri/Cargo.toml
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
git diff --check
```

如果没有 Rust、Tauri 配置或 capability 变更，可以在中间阶段不重复运行 Rust 全套，但最终候选仍需执行完整发布验证。

## 8. 真实 Tauri 验收

### 8.1 基础陪伴

- 正式低频配置下连续运行至少 60 分钟，没有高频动作、卡死或持续占用前台。
- 临时调试配置下可观察 `stretch`，恢复正式配置不需要修改业务代码。
- 用户拖动、打开菜单、单击动作、安全停止或退出能立即打断自主行为。
- 自主行为完成后回到合法待机状态，pivot、图层和点击穿透不漂移。

### 8.2 模式与偏好

- 陪伴模式按设置低频触发。
- 专注模式频率明显低于陪伴模式。
- 安静和休眠模式在长时间运行中不触发空闲动作。
- 用户关闭自主陪伴后，切换模式、重启和 HMR 都不会把它重新开启。
- reduced motion 和动画强度正确约束所有新表现。

### 8.3 对话状态

- 用户在绨络对话框输入时进入 `listen`，不会读取或诊断输入内容。
- 流式生成、取消、报错、窗口关闭和 TTS 中断后都不会卡在 `listen` 或 `speak`。
- 安静/休眠模式、聊天状态和拖动之间不会互相误恢复。

### 8.4 事件与隐私

- 番茄钟、音乐和插件事件不会产生重复反应。
- 插件失败不能显示成功反馈，未知事件安全忽略。
- 没有新增网络请求、系统权限、原始窗口读取或 capability 扩张。
- 诊断导出仍然不包含敏感正文和原始事件 payload。

## 9. 明确不纳入 Preview.3

- 第二套服装、运行时换装和跨服装动作重定向；继续等待 M9 的真实素材。
- 在线插件市场、第三方安装脚本和进程内插件代码。
- 自动调用 LLM、主动模型聊天或后台付费请求。
- 前台窗口标题、应用内容、键盘记录、剪贴板或音频内容读取。
- 神经 TTS、语音识别、麦克风监听或口型音素识别。
- 大规模重画小洛宝、切换 Live2D/Spine/Rive 或重写 Animation Studio。
- 窗口边缘/任务栏吸附；该项可在 Preview.3 稳定后作为独立桌面体验任务实现。
- 为增加动作数量而复制当前动作、伪造第二套服装或直接手改生产 motions JSON。

## 10. 风险与停止条件

| 风险 | 约束或回退 |
|---|---|
| 自主动作太频繁 | 默认低频、小时预算、保护期、总开关；先调策略，不增加更多动作 |
| 动作资产不足 | 使用 `stretch` 与程序化状态；可选 Clip 不阻塞发布 |
| 多来源重复反馈 | 统一 cue、去重键和调度互斥；不绕过现有 Host/Controller |
| React StrictMode/HMR 重挂载 | 所有 timeout、监听和动作请求有 cleanup 与幂等测试 |
| 角色状态卡死 | 持续状态单一来源，错误/取消/窗口关闭均显式回退 |
| 新能力扩大隐私范围 | Preview.3 不新增系统感知与联网；发现需要新权限时停止并重新评审范围 |

出现以下情况时停止增加表现，优先修复基础链路：

- 无法可靠中断或退出。
- 安静/休眠模式仍触发自主动作。
- 同一事件产生双重反应。
- 设置迁移丢失 Provider、密钥引用、记忆或插件状态。
- 诊断包含聊天正文、输入文本、模型参数或原始插件 payload。
- 新动作导致 bind pose、图层、pivot 或点击穿透回归。

## 11. 完成定义

Preview.3 可以进入发布验收，需要同时满足：

- 本地导演能使用现有动作形成低频陪伴闭环，无 LLM、无新增权限、无新增美术硬依赖。
