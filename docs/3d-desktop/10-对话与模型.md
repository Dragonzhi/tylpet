# 10 · 对话与模型

> **状态**：定稿（骨架成型，实现细节待 Phase 2 临近时补齐）
> **上游**：[01-产品愿景](01-产品愿景.md)、[02-角色系统](02-角色系统.md)、[03-屏幕与交互](03-屏幕与交互.md)
> **下游**：[08-实施路线](08-实施路线.md)

本档定义「她在想什么、说什么」的部分：模型接入、人格与状态如何进入 prompt、上下文组织、工具边界、隐私外发。她**说什么**归这里，她**怎么动**归 [02-角色系统](02-角色系统.md)、**怎么显示这句话**归 [05-表现层](05-表现层.md)。

## 2. 人格与状态注入（已决策）

**数值翻译成自然语言，注入 system prompt。** 人格与需求是数值，但 prompt 用自然语言——这决定她还是不是一个角色。

- 人格滑杆 → **形容词短语**，不把 `0.73` 这类数字直接喂给模型；
- 当前需求、天气、时段、正在进行的活动 → 编译成一段简短的「当前状态描述」；
- 状态描述作为 system prompt 的固定组成部分，**每次请求重新计算**（它不是缓存文案）；
- 人格→短语、状态→描述的**映射表写在角色包 JSON** 中，不硬编码——这是「人格归属角色包」的自然延伸，换角色即换说话方式。

**为什么不让模型读状态**：映射表已经把状态翻译进去了，再给只读工具是冗余 token。这条同时是第 4 节「零工具」的前提。

## 3. 上下文组织（已决策）

三层结构，超出即丢弃：

```text
[ system ]   人格映射短语 + 当前状态描述        （每次请求重算）
[ 记忆   ]   memory.v1 中的长期记忆摘要          （有限条目）
[ 历史   ]   最近 N 轮消息                       （超出丢弃）
```

- 在 2D「只保留最近消息」的基础上**补上前两层**；
- 完整聊天**永不进入长期持久化**——只有用户手动保存、确认模型候选、或显式记忆指令自动保存模式下的条目才进 `memory.v1`（已锁定的隐私边界，见 [02-角色系统](02-角色系统.md) 第 9 节）；
- 模型对记忆只有 `memory_propose` **候选**能力，没有直接写入 / 删除 / 修改记忆或改变羁绊的权限（已锁定，不随本档改变）；
- 最近 N 轮的具体轮数与 token 预算在 Phase 2 实现时定标，当前只锁定三层结构。

## 4. 工具边界（已决策）

**第一阶段零运动工具，LLM 不能直接指挥她做任何动作。**

- 她不能切换活动、不能改变世界——行为由确定性的需求 / 活动调度器驱动（[02-角色系统](02-角色系统.md) 第 4 节）；
- 这条保证了两件事：**可复现验收**（她的行为不取决于某次模型输出），以及**她的生活不由玩家意志左右**；
- 表现层效果（3D 文字、口型、TTS、看向屏幕）由表现层自身按规则触发，不由模型决定；
- 「零工具」限定的是**运动通路**。在这之外存在一条受限的**内感受写入**通道（见第 5 节），它是唯一允许模型影响角色内部数值的接口；
- 未来若开放表现层微动作等运动能力，须另立白名单与频率限制，且不得开放读写世界或记忆的能力。

## 5. 内感受写入边界（已决策）

模型对角色内部数值的影响遵守一条单向边界：**能写感受，不能写行为。**

| 层级 | 可否由模型写入 | 例子 |
| --- | --- | --- |
| 内感受（需求 / 情绪） | 可，受限 | 「这次对话让她开心了」→ `mood` +0.1 |
| 羁绊（关系强度） | 可，极小步长 | 长期互动的累积微调 |
| 活动（行为） | 不可 | 不能指定「现在去漫步」 |
| 运行态（五态） | 不可 | 不能切换 Dormant / Focus |
| 世界与物件 | 不可 | 与第 4 节一致 |

**为什么划在这里**：

1. **主体性**。行为一旦可被模型直接指派，她就退化为执行器，[02-角色系统](02-角色系统.md) 第 8 节的主体性边界与「生活不由玩家意志左右」当场失效；
2. **时滞即人感**。内感受是慢变量，写入后要经过调度器运算与需求累积才表现为行为倾向，中间天然带时滞。你说一句好话，她不会立刻蹦起来，而是情绪缓慢抬升，过一会儿才更主动地靠近屏幕。换成直接指令，这个延迟不存在，角色变成即时响应装置，人感随之消失。这是本设计里性价比最高的一处「白捡」的自然感。

**与神经拟态的对应**（这套对应有实际分层依据，不只是修辞）：

| 本档概念 | 神经类比 | 特征 |
| --- | --- | --- |
| 人格滑杆 | 神经调质 | 只调增益，不传信号 |
| 需求值 | 内分泌 | 慢、弥散、全局、有惯性 |
| 运行态五态 | 唤醒度 | 决定整体激活水平 |
| 调度器 | 脊髓 / 运动中枢 | 只执行，不理解 |

**约束（全部写在角色包 + 全局配置，不硬编码）**：

- **字段白名单**：只有 `needs.*` 与 `bond.*` 的若干字段可写，其余一律丢弃；
- **值域上限**：单次写入的绝对值上限（如情绪单次 ±0.1），防止一次对话把状态推到底；
- **频率限制**：单位时间内的写入次数与总量预算，防止长会话持续灌注；
- **不写记忆**：本通道与 `memory_propose` 候选机制同构，模型只能**提议**，落库仍走用户确认流程（[02-角色系统](02-角色系统.md) 第 9 节）；
- **不写判定**：拒绝 / 延后由 [02-角色系统](02-角色系统.md) 第 8 节的确定性公式判定。模型可以写「她此刻不想动」这种感受，但不能决定「这次拒绝」。判定结果作为结构化字段注入「当前状态描述」，模型只负责把这句话说出来。

本节的边界同时回答了第 8 节中「拒绝文案由谁撰写」的「谁」：措辞归模型。

**降级**：无 key / 离线时不写入任何内感受，需求按 02 档的自然速率变化（见第 7 节）。

## 6. 条件反射底层（已决策）

「她慢慢形成某种习惯」这类表现，底层是**确定性的联结表，不由模型实现**。

**机制（巴甫洛夫三要素的工程对应）**：

| 要素 | 实现 |
| --- | --- |
| 配对 | 刺激 A（如「夜间 + 点击屏幕」）与结果 B（如「聊天发生」）在同一时间窗内共现 |
| 形成 | 共现计数达到阈值，解锁一条原本不触发的响应倾向 |
| 消退 | 长期不再共现，联结强度按衰减率回落，归零后移除 |

- **数据结构**：联结表（刺激签名 → 强度 → 触发的响应倾向 ID），与角色档案分开存放；
- **触发路径**：联结强度只作为**调度评分的修正项**参与运算，不直接触发行为，与第 5 节同一条原则：改的是倾向，不是动作；
- **与羁绊的区别**：羁绊是长期累积、不衰减的关系量（[02-角色系统](02-角色系统.md) 第 9 节）；条件反射是可消退的短周期联结，两者不共用数值；
- **挂载点**：复用 [02-角色系统](02-角色系统.md) 第 8 节的轻量记忆事件与「活动结果」，不需要新的运行时机制。

**模型参与的边界**：只有当「学到了什么」涉及语义理解时（如把用户某个口头习惯与某个活动关联），模型才参与，且只输出**联结强度建议**，仍不执行动作，也不直接写联结表。

**为什么底层不用模型**：计数与衰减是纯运算，模型参与会引入延迟、成本与不可复现，而可复现验收是第 4 节明确锁定的红线。

## 7. 无 key / 离线行为（已决策）

**降级为离线 Mock。**

- 检测到 API key 缺失或请求失败时，自动切到离线 Mock 的确定性回复，玩家仍能立刻跟她说话；
- 复用 2D 的 `ChatProvider` 契约与离线 Mock 实现，不新增分支逻辑；
- **首次启动**引导填写 key，并在此给出**外发告知**：聊天内容会发送到用户配置的模型端点，可随时关闭；
- 不内置官方示例 endpoint（避免承担费用与滥用责任），不做本地大模型（与 60fps 渲染预算冲突，见 [07-渲染与性能](07-渲染与性能.md) 第 4 节）。

## 8. 待定项（Phase 2 实现前补齐）

- 人格滑杆 → 形容词短语的**完整映射表**（安静观察者的五维各给一组词）；
- 「当前状态描述」的**具体句式与字段范围**（精力 / 好奇 / 无聊 / 情绪 / 天气 / 时段 / 当前活动，哪些进、怎么措辞）；
- 最近 N 轮的**轮数与 token 预算**定标；
- 长期记忆摘要进入 prompt 的**压缩策略**（时间衰减？按羁绊等级取条数？）；
- 面对面拒绝（[02-角色系统](02-角色系统.md) 第 8 节判定为拒绝时）那句文案的**句式基调与兜底回落方式**。「谁写」已由第 5 节定为模型，此处待定的是风格与请求失败时的回落；
- 离线 Mock 的**回复语料规模与风格**（是否复用角色包的映射表来让 Mock 也有角色感）；
- 外发告知的**具体文案与可关闭粒度**（按会话关闭还是按端点关闭）。
