# 11 · 跨端与外部接口

> **状态**：草案（待评审，尚未采纳）
> **上游**：[01-产品愿景](01-产品愿景.md)、[02-角色系统](02-角色系统.md)、[04-游戏外壳](04-游戏外壳.md)、[10-对话与模型](10-对话与模型.md)
> **下游**：无。本档采纳后需要回改 04、10 的相应小节（见第 4 节与第 7 节）。

本档定义「世界可以脱离游戏窗口而存在」这件事：她的生活不由某一个前端决定，游戏与文本端（QQ 等）是同一个世界的两个观察孔。

**目标场景**：她在 QQ 里说自己在看雨；此时打开游戏，能看到她正坐在窗边看着外面的雨。

## 1. 核心原则：唯一状态源

**跨端一致性不靠同步，靠共享同一份世界状态。**

- 世界运行时是**唯一事实源**，各前端只是视图，都不持有权威状态；
- 只要文本端与游戏端读取同一份状态，「她说在看雨」与「她在看雨」自动一致；
- 因此本档**不引入任何同步协议**：不做消息队列、不做双向 diff、不做冲突合并。一致性是唯一状态源的副产品，不是需要额外维护的东西。

### 1.1 一致性下限原则（关键）

- 她在任何前端说出的话，**必须能被当前世界状态解释**；
- 反向不要求：她不必穷尽状态。可以说「在看雨，有点冷」，也可以说「下雨了，我想你了」；
- **措辞自由，事实底唯一**。禁止模型在任何前端编造世界里没有发生的事。

这条下限由 [10-对话与模型](10-对话与模型.md) 第 2 节的「状态描述注入」天然支撑：只要世界状态里存在「天气=雨、当前活动=观察屏幕」，她在文本端的回应就会自带上下文，不需要为跨端单独写一套话术。

## 2. 架构：headless 世界核心 + 可插拔前端

```text
┌──────────────────────────────────────────────────┐
│ World Core（headless 常驻）                       │
│  世界状态 / 需求推进 / 世界时间 / 天气 / 活动调度   │
│  记忆与羁绊 / 模型调用                            │
│  本地接口：127.0.0.1 HTTP + WebSocket             │
└──────┬──────────────────────────────┬────────────┘
       │ 重前端                        │ 轻前端
┌──────▼───────────┐        ┌─────────▼──────────┐
│ 游戏客户端        │        │ 文本端              │
│ 渲染 / 3D / TTS   │        │ QQ bot 等           │
│ 屏幕交互 / 运行态 │        │ 只读写消息与状态摘要 │
└──────────────────┘        └────────────────────┘
```

- **世界核心**：无渲染、无窗口，进程可独立常驻；
- **重前端**：当前 Tauri 游戏客户端，承担 3D 渲染、TTS、屏幕交互与运行态五态；
- **轻前端**：只做文本收发与状态读取，不含渲染。

**参考先例**：Neuro-sama 采用的就是这个结构，一个核心，Twitch 聊天、游戏、TTS、动作驱动均为接入它的前端，官方另维护一套 Neuro API 供外部程序接入；本地复刻项目 `kimjammer/Neuro` 亦为「核心 + 前端/控制面板」分离。

### 2.1 改造范围

本档是 [01-产品愿景](01-产品愿景.md) 第 2 节「两种形态共用同一套世界运行时」的延伸，从「两种窗口形态」扩为「两种前端形态」。

第一阶段**不要求实现**，但要求在动工时就遵守一条约束：**世界逻辑不得写进渲染层或 Tauri 窗口生命周期**。否则未来抽取核心的成本会远高于现在多花的那点结构成本。这是本档对第一阶段唯一有约束力的部分。

## 3. 前端分层与能力边界

| 能力 | 重前端（游戏） | 轻前端（文本） |
| --- | --- | --- |
| 读世界状态 | 可 | 可（摘要粒度） |
| 推进渲染 | 负责 | 无 |
| 发起对话 | 可 | 可 |
| 触发主动行为 | 可，按需求阈值 | 受限，见第 5 节 |
| 写入内感受 | 不可（同 [10](10-对话与模型.md) 第 5 节） | 不可 |
| 修改世界 / 活动 / 运行态 | 不可 | 不可 |

轻前端不拥有运行态五态（那由渲染侧与窗口焦点驱动），只有「在线 / 离线」两态。五态是重前端的内部概念，不向文本端暴露。

## 4. 「退出」语义变更

**问题**：[04-游戏外壳](04-游戏外壳.md) 第 4 节规定失焦超过 5 分钟完全暂停（停止渲染与生活结算），第 2 节规定退出即结束。在跨端形态下，这两条与「世界持续存在」正面冲突。

**建议修订方向**（采纳本档后同步修订 04 档）：

- **退出游戏 = 关闭渲染前端**，不等于停止世界运行；
- 世界核心按自己的生命周期常驻（托盘常驻或独立后台进程），文本端需要它在线；
- 失焦暂停改为「停止渲染」，世界结算继续；
- 用户界面应能明确区分并分别控制两种语义：**关闭窗口** / **退出世界**。

这是本档与既有定稿唯一的正面冲突，取舍需要明确决定，不默认生效。

## 5. 主动行为的端差异策略（建议）

游戏里她走近屏幕是温柔的低频动作；文本端主动发消息是侵入性的，你在开会时收到一句「我在看雨」就是打扰。

| 维度 | 游戏前端 | 文本前端 |
| --- | --- | --- |
| 触发依据 | 需求阈值（[02](02-角色系统.md) 第 8 节） | 需求阈值 + 更严的额外门槛 |
| 频率 | 按活动节奏偏好 | 独立配额（如每日上限） |
| 时间窗 | 全时段 | 安静时段内不发 |
| 失败代价 | 无（不看就不看） | 打扰（用户可能在开会） |

推论：[02-角色系统](02-角色系统.md) 第 4.1 节的「活动节奏偏好」全局倍率需要按前端拆分为独立策略，同一份需求值在两个前端的表达强度不同。

## 6. 回应时延由世界状态驱动（建议）

文本端的回应延迟不应是固定值，而应是她当前活动的函数：

| 她的当前活动 | 文本端表现 |
| --- | --- |
| 观察屏幕 / 站立待机 | 接近秒回 |
| 网格漫步 | 稍慢 |
| 休息发呆 | 明显延迟，或回一句「我刚醒」 |

- 延迟可由活动剩余时长推导（[02](02-角色系统.md) 第 4.5 节的预计时长）；
- 这个延迟代表她真的在处理别的事，而不是模拟打字手感；
- 它同时是跨端一致性最直接的证据：用户从「她回得慢」里感到她在别处生活。这一条不需要额外系统，是唯一状态源的副产品。

## 7. 跨端记忆与隐私边界

**张力**：跨端一致性会诱使人把完整聊天记录存下来，好让任何一端都能接上上下文。

**结论：不破例。** [02-角色系统](02-角色系统.md) 第 9 节锁定的「完整聊天永不长期持久化」在跨端形态下继续有效。

- 跨端的「记得」靠**记忆摘要**，不靠原始记录；
- 文本端对话同样只保留最近 N 轮（[10](10-对话与模型.md) 第 3 节三层结构），超出即丢弃；
- 落库仍走用户确认流程（`memory_propose` 候选）；
- 与世界无关的闲聊内容不进任何一端的历史。

这条边界在跨端形态下更容易被绕过，因此需要在世界核心侧实现为**统一策略**，而不是各前端各自遵守。

## 8. 媒介自觉（建议）

同一个她，在不同媒介下的表达方式应当不同：

- 游戏内：3D 文字 + TTS + 动作，语气偏「被看着」；
- 文本端：纯文本，应有打字媒介的自觉（消息长短不一、偶发撤回、偶发错别字），而不是每句都完整工整；
- **人格一致，表达通道不同**。同一个人在电话里和微信里本来就不一样。

## 9. 本地接口（建议）

| 项 | 建议 |
| --- | --- |
| 传输 | 127.0.0.1 上的 HTTP（请求 / 响应）+ WebSocket（状态推送与消息流） |
| 绑定 | 只绑回环地址，不监听外网 |
| 鉴权 | 本地 token；仓库既有日报站使用 HMAC 鉴权，做法可复用 |
| 端口 | 固定或写入配置文件，占用冲突时回落并记录 |
| 消息结构 | 文本端只上报「用户消息」，只读取「她的回复 + 状态摘要」；不接受文本端写入原始世界状态 |

文本端不是第二个大脑，它的权限与 [10](10-对话与模型.md) 第 5 节的内感受通道同级，不因为跨端而扩张。

## 10. 第一阶段不做

1. 不实现世界核心抽取（本档只锁定边界，防止世界逻辑写死在渲染层）；
2. 不做多人共享世界（一个世界只属于一个用户）；
3. 不做公网接入与远程访问；
4. 不做文本端的主动推送（第 5 节配额方案随世界核心一起实现）；
5. 不实现跨端聊天记录同步。

## 11. 待定项

- 世界核心的进程形态：Tauri 托盘常驻 / 独立后台服务 / 由首个前端拉起；
- 文本端是否完整支持「她先发消息」的主动能力，还是只做被动应答；
- 安静时段的具体定义与用户可配置粒度；
- 本地接口的鉴权方式与凭据存储位置；
- 跨端时「她在游戏里见过你」与「她在文本里和你聊过」是否需要区分记忆来源。
