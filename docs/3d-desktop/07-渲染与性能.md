# 07 · 渲染与性能

> **状态**：定稿
> **上游**：[01-产品愿景](01-产品愿景.md)、[02-角色系统](02-角色系统.md)
> **下游**：[08-实施路线](08-实施路线.md)

本档定义 3D 渲染管线、视觉参数与性能预算。技术栈为 Three.js + `@pixiv/three-vrm`，先用 Three.js 验证版，质量不达预期再评估更换引擎。

## 1. 角色材质（VRM / MToon）

- **标准**：VRM 0.x 或 1.0，`@pixiv/three-vrm` 加载；
- **风格**：纯正二次元番剧赛璐珞（Anime Cell-Shading）；
- **阴影阈值**：`ShadeToony` 初始目标 0.90~0.95，硬朗切边；
- **阴影色**：取基底色的冷暖衍生色，拒绝发灰变脏；
- **面部保护**：降低不利于面部识别的斜射阴影，保证五官白皙通透；
- **描边**：MToon / Inverted Hull 风格细描边，颜色取邻近深色而非纯黑；
- **面数预算**：约 2.5 万~3.5 万三角面，收敛贴图与材质数量。

**MToon 验收判据**（Phase 0 Spike 2 门禁项）：
- `ShadeToony` 0.90~0.95 下切边硬朗可辨，无发灰、无脏色块；
- 三点光下面部无灰调阴影斑块，五官白皙通透；
- 阴影色为基底色的冷暖衍生色，而非直接降明度的灰色；
- 描边在 1080p 下可见、连续、不闪烁，颜色取邻近深色而非纯黑。

## 2. 工作室三点布光

| 灯光 | 位置与色调 | 作用 |
| --- | --- | --- |
| Key 主光 | 前上方，暖白 #FFF8F0，强度约 1.8 | 照亮面部和主体 |
| Fill 补光 | 侧前方，冷蓝白 #D0E0FF，强度约 0.8 | 保持暗部通透 |
| Rim 轮廓光 | 后上方，近白色，强度约 3.0 | 勾勒发丝、肩线和四肢 |

数值是调参起点。第一版不依赖真 Bloom；氛围使用灯光、低成本材质、暗角和 Shader 模拟。

## 3. 地面网格（游戏内形态）

全屏游戏中的网格是空间底座而非桌面叠加层：

- 程序化生成的无限网格（Shader 或有限线段，不用大地面模型）；
- 保留经典配色：普通线半透明灰白，X 轴 #EB4034，Y 轴 #43B549；
- 网格向远处淡出；角色脚底有柔和接触阴影（羽化椭圆面片，不用高成本级联阴影）；
- 文字坠落碰撞面统一为地面 y = 0；
- 相机：PerspectiveCamera，FOV 约 38°，俯角 12°~15°，完全固定，无鼠标视差。

## 4. 性能预算

60fps 是基线目标。设置中提供低 / 中 / 高三档画质，默认中档，低档目标 30fps 可玩。

| 项目 | 低 | 中 | 高 |
| --- | --- | --- | --- |
| 渲染分辨率倍率 | 0.5x | 0.75x | 1.0x |
| 抗锯齿 | 关 | FXAA | SMAA |
| 阴影质量 | 仅接触阴影 | 接触阴影 | 基础实时阴影 |
| SpringBone | 关 | 半帧率更新 | 全帧率更新 |
| 文字粒子特效 | 关 | 简化 | 完整 |

其他约束：

- 显存目标不超过约 400MB（以实测为准）；
- VRM 贴图压缩，单张不超过 2048；
- 文字粒子有并发上限、队列和回收。

## 5. 动画质量验收（Phase 0 Spike 2 门禁）

Spike 2 采用**逐项量化门禁**：四项全过才算通过，任意一项不通过都需要记录差距并决定对策（换模型 / 换动作资产 / 换引擎）。

| 项 | 通过判据 |
| --- | --- |
| MToon 质感 | `ShadeToony` 0.90~0.95 切边硬朗可辨；三点光下面部无灰调阴影斑块、五官通透；阴影色为基底色冷暖衍生不发灰；描边 1080p 可见且不闪烁 |
| 动作混合 | 过渡 ≤ 0.3s；根骨骼位置 / 旋转连续无跳变；同身高动作间 Hip 高度差 ≤ 2cm；切换前后无穿模 |
| LookAt | 水平 ±60°、垂直 ±30° 内平滑跟随目标；无翻眼、无高频抖动；超出范围时以转头 + 躯干代替眼球极限 |
| SpringBone | 关键链条 ≤ 20 根；中画质（半帧率更新）下仍稳定 60fps；静止无自激抖动；走动时裙摆不穿腿、马尾不穿背；停止后有阻尼衰减、不停摆 |

验证方法：录制角色在待机→漫步→休息→观察屏幕→回到待机的完整循环，以及 LookAt 在左右上下极限间移动的过程，逐项核对。

### 5.1 自然感：程序化加性微动层（已决策）

自然感的主引擎是**常驻的加性微动层**，不是变体资产数量。真实感最大的杠杆是「永不精确重复」与「永不真正静止」——玩家觉得假，从来不是因为动作少，而是因为同一个循环播第二遍时一模一样。

**实现**（Phase 1 起）：

| 层 | 内容 | 性质 |
| --- | --- | --- |
| 呼吸 | 胸椎 / 锁骨的周期性小幅起伏 | 程序化，常驻 |
| 重心 | 髋部与脚部的缓慢重心偏移，双足交替承重 | 程序化，常驻 |
| 眨眼 | 无规律眨眼，间隔带随机扰动 | 程序化，常驻 |
| 视线惯性 | LookAt 目标的平滑趋近与轻微过冲，锁定后缓慢游离 | 程序化，常驻 |

**规则**：

- 微动层与活动动画**叠加**，不替换活动片段，也不改变活动 ID；
- 微动相位在每次会话启动时随机化，因此**同一个循环片段播两次也不相同**；
- 微动由代码生成，**不消耗动画资产、不受世界包影响**，因此一致性天然有保证；
- 微动层是所有自然感手段里性价比最高的一层：零新资产、跨世界跨天气一致。

**验收**：连续观察 10 分钟，不得出现「完全静止超过 3 秒」或「同一动作精确重复两次」；此项并入 Phase 1 验收（依赖真实资产与真实渲染环境，不放 Phase 0）。

### 5.2 变体与资产规范（已决策）

**变体是辅助，不是主引擎**：每个活动可挂多个循环片段，进入活动时按角色包声明的权重抽取，且片段起始相位随机。但——**Phase 1 与默认房间阶段每活动只做 1 个片段**，先立一致性基线；多变体（每活动 2~3 个）留到有余量后追加。

理由：变体每加一个就多一份一致性风险。绝区零级别的动作一贯性来自整个团队多年打磨，本项目资产预算远小于此，因此一致性必须先于变化建立。

**资产规范**（贯穿所有角色动作资产）：

- 同一角色的全部片段须**同源**（同一动作库 / 同一作者 / 同一套规范），禁止混用风格迥异的资产；
- 统一**根骨骼归一化**、统一 **Hip 高度基线**、统一**帧率**，避免「拼接味」（骨骼尺度不同、脚不贴地、风格突变）；
- 状态切换统一走过渡时长（见第 5 节门禁），不做硬切。

**归属**：变体与小动作习惯写入**角色包**，与世界包正交——她的习惯属于她本人，不随更换世界而改变（与人格同源，见 [02-角色系统](02-角色系统.md) 第 5 节）。

## 6. 动作来源与生成式动画远景

### 6.1 当前决策：预制 VRMA 为唯一动作来源（已决策）

- 第一阶段与默认房间阶段，角色动作**全部来自预制 VRMA 文件**，优先使用现成 VRMA / Mixamo 资产；
- 不引入任何运行时动作生成模型，不为推理预留 GPU 预算——显存与帧率预算见第 4 节，生成式模型会直接挤占渲染资源；
- 动作资产的质量仍按第 5 节 Spike 2 的四项门禁验收。

### 6.2 为什么不用运行时生成（已记录的取舍）

业界已有成熟的 text-to-motion / motion foundation model（如 NVIDIA ARDY、UniMate、Uthana、MotionBricks），但与本项目结构性错配：

- 这类模型的价值在**种类与表现力**，而本项目已锁定「低频、长时长、可复现验收、60fps 渲染预算」；
- 运行时推理会与 MToon + SpringBone 抢同一块 GPU，且产出动作不可控、不可复现，直接冲击 Phase 0/1 的验收逻辑；
- 生成模型适合「解除作者的动作类型限制」，不适合「在玩家机器上实时决定她怎么动」。

### 6.3 接缝：只定义契约，不实现生成器（已决策）

为了让远期愿景可以低成本接入，动画层定义一个**动作来源接缝**：

- 上游消费者（五活动调度器、行为表现）只依赖「取某活动的动画片段」这一契约，不关心片段来自文件还是模型；
- 第一阶段只存在**预制 VRMA 实现**，生成器实现留空；
- 接缝只用于隔离来源，**不引入插件机制、不引入模型下载、不引入用户可见开关**。

这样做的理由：接缝的成本是一次接口定义，收益是未来不会为了「换动作来源」而重构调度与表现层。但**不预先实现调用方**——没有调用方的抽象会腐化。

### 6.4 远期愿景（不在当前承诺范围）

实时生成定位为**可开关的愿景**，默认关闭，且远晚于默认房间阶段。若未来启动，需先解决：GPU 预算重新分配、动作可复现性、与已锁定活动 ID 的关系、以及质量验收标准的重定义。启动前必须重新评估，不改动当前任何验收判据。

## 7. 性能验收

- 主显示器 1080p / 2K 下中画质稳定 60fps；
- 连续运行 30 分钟的 GPU、内存和帧率曲线记录；
- 失焦低帧率与 5 分钟暂停行为验证（规则见 [04-游戏外壳](04-游戏外壳.md)）。
