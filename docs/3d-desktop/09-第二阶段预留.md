# 09 · 第二阶段预留：透明桌面模式

> **状态**：草案（不在第一阶段实施）
> **上游**：[01-产品愿景](01-产品愿景.md)
> **说明**：本档是原“桌面叠加形态”的技术结论存档。当全屏游戏阶段完成、需要回到桌面叠加形态时，以本档为起点重新验证（窗口与性能环境可能已变化）。

## 1. 形态定义

世界以全屏透明无边框置顶窗口叠加在 Windows 桌面上：

- 网格横贯屏幕底部，向上与两侧平滑淡出，网格之外透出原生壁纸；
- 角色站在屏幕右侧偏右下（横向 75%~80%），高度约占屏幕 45%~50%；
- 固定透视相机，FOV 约 38°，俯角 12°~15°，完全固定镜头；
- 桌面图标、任务栏、右键菜单必须完全不受影响。

## 2. 地面网格参数

| 参数 | 值 |
| --- | --- |
| 普通网格线 | RGBA (255,255,255,0.15)，约 1 CSS px |
| X 轴 | #EB4034，横向贯穿底部 |
| Y 轴 | #43B549，从原点向景深延伸 |
| 原点 | 角色脚底附近，屏幕右下偏中 |
| 衰减 | 向上从约 0.2 平滑到 0，两侧径向淡出 |
| 实现 | 程序化 Shader 或有限线段 |

接触阴影使用羽化半透明椭圆面片，随站姿、坐姿和角色位置更新。

## 3. 动态点击穿透

**事实前提**：Web 层无法把已消费的鼠标事件还给桌面，穿透只能由 Win32 窗口样式 / Tauri 控制。

主路线：

1. 窗口默认 `WS_EX_LAYERED | WS_EX_TRANSPARENT`（Tauri `set_ignore_cursor_events(true)`）；
2. Rust 用 Win32 `GetCursorPos` 约 30Hz 轮询物理坐标（穿透态下 WebView2 收不到 mousemove）；
3. DPI 换算：物理像素 ÷ `devicePixelRatio` → CSS 像素 → NDC → Raycaster；
4. 只对角色和当前允许交互的对象命中；
5. 命中 → 关闭穿透进入激活；移出包围圆（带滞回）→ 恢复穿透。

已知缺陷：切换延迟 1~2 帧；极速甩动可能漏命中。用滞回逻辑 + 稍大包围圆缓解。

备选：`WH_MOUSE_LL` 低级鼠标钩子（命中自家区域吞掉事件，未命中放行）。回调必须微秒级返回，复杂度高，能不上就不上。

## 4. 桌面模式性能预算

| 项目 | 预算 |
| --- | --- |
| 帧率分级 | Dormant 0fps / Ambient 15fps / Aware/Engaged 60fps |
| 像素比 | ≤ 1.25 |
| 显存 | ≤ 约 400MB |
| 降级 | 全屏游戏或前台高负载 → Dormant |

## 5. 与桌面图标的关系（远期）

原设想中角色可以“把桌面当作窗外世界”：观察图标布局、看向图标、对桌面变化反应。接入时需要独立的 Desktop Bridge（观察图标元数据、活动窗口、用户点击），默认只开放观察权限，操作类权限需用户单独授予。第一阶段不涉及，见 [03-屏幕与交互](03-屏幕与交互.md) 第 8 节。

## 6. 复用前提

- 全屏游戏阶段的世界运行时（角色、活动调度、屏幕交互协议）应设计为与窗口形态解耦，使本档的窗口层改造不牵动业务层；
- 重新启动本阶段前，需重做透明窗口性能与穿透手感的真实 Tauri 验证。
