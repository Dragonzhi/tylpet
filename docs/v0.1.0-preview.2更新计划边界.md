# v0.1.0-preview.2 更新计划与边界

> 状态：已实现并通过真实 Windows/安装验收与用户试用，可进入 `v0.1.0-preview.2` 发布
>
> 最后更新：2026-07-28
>
> 本文档定义 `v0.1.0-preview.2` 的单版本工作范围、非目标和验收口径。它不是长期路线图，也不替代 `计划.md`。

## 1. 版本定位

`v0.1.0-preview.2` 定位为“用户实际试用验证版”。当前项目的主要基础能力、发布流程和 GitHub Actions 已经具备，本版本不再以重复补齐已验证的 P0 为目标，而是把产品交给真实用户使用，验证陪伴体验和行为边界。

本版本的核心问题是：

> 用户是否愿意长期打开它，以及它是否能够在不打扰用户的前提下提供稳定、可理解的陪伴感。

## 2. 范围判断原则

### 2.1 发布前必须解决

以下问题仍然属于硬阻塞项：

- 崩溃、数据丢失、无法退出或无法恢复。
- 安装包无法安装、覆盖安装破坏数据，或升级后无法启动。
- 密钥、聊天内容、插件数据或系统感知数据发生未授权外发。
- 绕过 `BehaviorScheduler`、权限校验或用户确认的高影响行为。
- CI、版本同步、构建产物和 Release 流程无法重复执行。

### 2.2 可以交给用户试用验证

以下问题不应在没有用户反馈前无限扩大范围：

- 待机动作是否自然，频率是否合适。
- 音乐、TTS、Agent 和番茄钟反馈是否打扰。
- 角色是否需要更多主动行为。
- 不同设备上的性能感受和长期运行稳定性。
- 角色模式的默认值和名称是否容易理解。

用户试用期间发现的问题，先记录为反馈或缺陷；只有涉及数据、安全、崩溃或核心行为错误时，才提升为发布阻塞项。

## 3. 本版本交付范围

### 3.1 角色模式

增加统一的角色行为模式，优先复用现有设置、调度器和观察事件能力：

- `companion`：正常陪伴，允许低频主动行为和已启用的系统反应。
- `focus`：配合番茄钟，降低聊天外的主动打扰。
- `quiet`：暂停 Agent、TTS 和外部观察反应，只保留必要的基础动画。
- `sleep`：低频待机，保留托盘、快捷键和立即停止路径。

模式必须由本地策略控制，不能让模型自行切换，也不能绕过用户的总开关、安静时段和 reduced motion 设置。

### 3.2 行为编排和打扰控制

本版本重点不是增加大量动作，而是把已有动作编排得更自然：

- 明确用户操作、系统反馈、Agent 和环境反应之间的优先级。
- 复用 `BehaviorScheduler` 的冷却、互斥、中断和安全停止能力。
- 避免多个来源同时触发动作，减少重复招手、连续律动和高频表情。
- 模式切换、菜单打开、用户拖动和立即停止后，行为能够及时收束。
- 为主动行为保留可诊断的来源和结果，但不记录敏感 payload、聊天内容或工具参数。

如果已有动作资产已经足够，本版本不以“新增动作数量”作为验收指标；新增动作只在能通过 Animation Studio 到运行时的完整链路验证时纳入。

### 3.3 用户理解和反馈闭环

- 首次启动说明离线 Mock、外部 Provider、Agent、TTS、系统观察和数据位置。
- 设置页明确展示当前模式以及会被该模式关闭或降低的能力。
- 提供脱敏诊断导出或复制入口，便于用户反馈问题。
- 保留手动反馈方式，不默认增加遥测、行为追踪或后台上传。
- 发布说明列出已知限制、测试范围和不构成稳定兼容承诺的部分。

### 3.4 Animation Studio 协作验证

Animation Studio 在本版本的目标是验证生产协作链路，而不是继续扩展大型编辑器功能：

- 使用编辑器制作或调整至少一个可发布动作。
- 验证 `artwork + rig + motions` 导出后能被桌宠加载。
- 验证缺失动作、版本不兼容和素材异常时的降级或明确拒绝。
- 保持编辑器和桌宠位于同一仓库，但通过共享 schema 和明确导出边界协作。

## 4. 明确不纳入本版本

- 第二套服装和运行时换装；等待真实素材、授权和 M9 的前置条件。
- 在线插件市场和第三方安装脚本。
- 任意 Shell、文件、进程或通用网络 Agent 工具。
- 完整聊天记录永久保存。
- macOS、Linux 或 ARM64 正式支持。
- 复杂的自动更新系统。
- 为了追求功能数量而进行渲染器或项目目录的大规模重构。

正式代码签名、自动更新和公开发行授权仍属于 M16 的发布决策，但不是本版本新增产品功能；若它们尚未满足发布条件，应明确标为限制，而不是伪装成已完成能力。

## 5. 实施顺序

1. 冻结模式、设置字段和默认策略，先补协议、迁移和单元测试。
2. 将模式策略接入现有调度器、TTS、Agent、番茄钟和观察事件，不新增绕过调度器的快捷路径。
3. 完成设置页、首次启动说明和脱敏诊断入口。
4. 用 Animation Studio 完成一个真实动作的制作、导出和运行时回归。
5. 构建预览安装包，邀请实际用户使用，集中收集打扰程度、稳定性、性能和理解成本反馈。
6. 根据用户反馈决定 `preview.3` 的修复内容，不在本版本中预先承诺更多大型功能。

## 6. 完成标准

本版本可以发布的最低条件：

- 四种模式的行为边界、默认值和关闭路径有明确实现与测试。
- 用户操作、立即停止、菜单和退出始终高于自主行为。
- 模式切换不会破坏设置、计时器、记忆、聊天或窗口位置恢复。
- 至少一个编辑器产出的动作通过桌宠真实运行时验证。
- 诊断信息不包含密钥、完整聊天、prompt、工具参数、终端输出或文件内容。
- 发布包可安装、可启动、可退出，已知限制已写入发布说明。

## 8. 当前实施结果

- 四种角色模式、设置 v10 迁移和纯策略测试已经实现；模式只收紧用户总开关，Agent 工具协议未获得模式写入能力。
- Agent、TTS、外部观察和基础动画已消费同一模式策略；专注模式降低环境反馈并延长冷却，安静/休眠模式会停止当前朗读、媒体状态和自主调度动作。
- 调度器暂停支持独立原因，避免拖动、菜单和模式之间互相误恢复；计时器与用户动作继续使用更高优先级。
- 设置窗口新增首次说明、模式影响预览、版本标识和脱敏诊断导出；诊断只允许有限状态字段，并通过 Rust 测试确认不会带出 endpoint、模型名、密钥或聊天内容。
- 生产资产测试继续验证 Animation Studio 导出的 `wave`、`bow`、`stretch`，并覆盖缺少非必需动作的能力降级、不兼容 schema、错误指纹和缺失绑定。
- 自动化与人工验收的事实记录统一维护在 [`v0.1.0-preview.2验收报告.md`](./v0.1.0-preview.2验收报告.md)；未勾选的真实窗口和安装项不得宣称已通过。
